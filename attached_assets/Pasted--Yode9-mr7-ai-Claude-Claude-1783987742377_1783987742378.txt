# برومبت شامل: رفع مستوى مشروع Yode9 (mr7-ai) ليقترب من Claude

استخدم هذا البرومبت كاملاً مع Claude Code (أو أي وكيل برمجي) داخل مجلد المشروع. نفّذ المهام **بالترتيب المذكور**، ولا تنتقل لمهمة تالية قبل التأكد أن السابقة تعمل فعلياً (اختبار حقيقي، لا افتراض).

---

## سياق المشروع

مشروع "Yode9 / mr7-ai" هو تطبيق دردشة بواجهة Claude-style Artifacts، مبني على:
- Frontend: React + Vite (`artifacts/mr7-ai`)
- Backend: Express 5 (`artifacts/api-server`)
- DB: PostgreSQL + Drizzle
- طبقة الذكاء: توجيه (routing) بين OpenAI/Anthropic/Cloudflare/Groq

الهدف: سد الفجوات الحرجة التالية بالترتيب، بدون كسر أي وظيفة تعمل حالياً.

---

## المهمة 1 (حرجة/أمنية): إصلاح عزل تنفيذ الكود

**المشكلة**: `artifacts/api-server/src/infrastructure/execution/FirecrackerSandbox.ts` يستخدم `child_process.spawn` عادي فقط. الحقول `cpuQuota`, `memoryLimitMb`, `diskLimitMb`, `networkDisabled`, `maxPids` معرّفة لكن **غير مطبّقة فعلياً** على العملية المنفّذة — أي كود قابل نظرياً للوصول للشبكة والملفات رغم الإعدادات.

**المطلوب**:
1. استبدل التنفيذ الحالي بعزل حقيقي باستخدام أحد الخيارين:
   - **Docker/OCI container** لكل عملية تنفيذ، مع:
     - `--network=none` لمنع الشبكة فعلياً
     - `--memory`, `--cpus`, `--pids-limit` مطبّقة عبر Docker/cgroups v2 مباشرة
     - نظام ملفات مؤقت (`--read-only` + tmpfs محدود الحجم) يُحذف بعد التنفيذ
     - مستخدم غير root داخل الحاوية (`--user`)
   - أو **gVisor (runsc)** كـ runtime إذا كانت البيئة تدعمه
2. أضف اختبار تلقائي (integration test) يتحقق أن:
   - كود يحاول عمل `fetch()` أو `require('net')` يفشل فعلياً (لا شبكة)
   - كود يحاول تجاوز حد الذاكرة يُقتل (OOM) خلال المهلة المحددة
   - كود لا يقدر يقرأ ملفات خارج مجلده المؤقت (`../../etc/passwd` مثلاً)
3. أعد تسمية الملف أو أضف تعليق صريح يوضح آلية العزل الفعلية المستخدمة (لا تترك اسم "Firecracker" إذا لم يُستخدم فعلياً — هذا مضلل).
4. حدّث `outputFiles` و`memoryPeakMb` ليعكسا قيماً حقيقية (حالياً ثابتة/فارغة).

**معيار القبول**: تشغيل كود خبيث تجريبي (محاولة اتصال شبكي، قراءة ملف نظام، استهلاك ذاكرة مفرط) يجب أن يُمنع فعلياً وتظهر رسالة خطأ واضحة، لا صمت.

## المهمة 2: توحيد طبقة الذكاء (إزالة التكرار)

**المشكلة**: يوجد مسار مزدوج:
- `artifacts/api-server/src/infrastructure/ai/AIOrchestrator.ts` — بدون تاريخ محادثة، بدون streaming حقيقي، غير مستخدم في `chat.ts`
- `artifacts/api-server/src/lib/ai-providers` — المستخدم فعلياً، فيه streaming حقيقي عبر SSE

**المطلوب**:
1. تحقق بالبحث (`grep -r "AIOrchestrator" artifacts/api-server/src`) من كل الأماكن التي تستورد `AIOrchestrator`.
2. إن لم يكن مستخدماً فعلياً في أي مسار تشغيلي حقيقي (routes)، احذفه أو ادمج منطقه المفيد (circuit breaker, model selection بالتكلفة/السرعة) داخل `ai-providers` كطبقة اختيار نموذج، مع الحفاظ على الـ streaming.
3. أضف لطبقة `ai-providers` الموحّدة:
   - تمرير **تاريخ المحادثة كامل** (messages array) وليس prompt واحد فقط
   - Circuit breaker لكل مزوّد (OpenAI/Anthropic/Cloudflare/Groq) حتى لا يتكرر الفشل بلا داع
   - Cache اختياري للطلبات المتطابقة تماماً (غير الحرجة)

**معيار القبول**: مسار ذكاء واحد فقط في الكود، موثّق في `replit.md` تحت "Architecture decisions"، وكل الاختبارات القديمة لـ chat.ts ما زالت تعمل.

## المهمة 3: حلقة أدوات فعلية (Agentic Tool Loop)

**المشكلة**: الأدوات مسجّلة في `tool-orchestrator-v2.ts` (26 أداة) لكن لا توجد حلقة واضحة "فكّر → نفّذ أداة → قيّم النتيجة → قرر التالي → كرر حتى الانتهاء" مشابهة لما يستخدمه Claude في المهام متعددة الخطوات.

**المطلوب**:
1. ابنِ دالة `runAgentLoop(userMessage, context)` في `api-server` تنفّذ:
   - إرسال الرسالة + قائمة الأدوات المتاحة (schemas) للنموذج
   - إذا رجع النموذج طلب استدعاء أداة (tool_use): نفّذ الأداة عبر `registry.get(name).handler(...)`، أرجع النتيجة للنموذج كـ tool_result، وكرر
   - حد أقصى لعدد التكرارات (مثلاً 15) لمنع حلقات لا نهائية، مع رسالة واضحة عند الوصول للحد
   - تسجيل كل خطوة (tool called, args, result, duration) في لوج قابل للعرض في الواجهة (شبيه بـ "شريط التفكير" في Claude)
2. اعرض هذه الخطوات في الواجهة (frontend) بشكل حي أثناء التنفيذ (streaming الخطوات وليس فقط النص النهائي).
3. تعامل مع فشل أداة واحدة دون إيقاف الحلقة كلها (أعد الخطأ للنموذج ليقرر بديلاً).

**معيار القبول**: طلب مستخدم يتطلب 3 أدوات متتالية (مثلاً: بحث ويب → استخراج بيانات → إنشاء ملف Excel) ينفَّذ تلقائياً بحلقة واحدة مرئية للمستخدم، بدون تدخل يدوي.

## المهمة 4: ربط الذاكرة الدلالية الحقيقية

**المشكلة**: `save_memory`/`recall_memory` يعتمدان بحث كلمات مفتاحية (`ILIKE`) رغم وجود أداة `generate_embeddings` جاهزة وغير مستخدمة معها.

**المطلوب**:
1. عند `save_memory`: احسب embedding للنص عبر `generate_embeddings` واحفظه في عمود `vector` (استخدم امتداد `pgvector` في Postgres — تحقق أولاً إن كان مثبتاً، وإلا أضفه في migration جديد بـ Drizzle).
2. عند `recall_memory`/`semantic_search`: احسب embedding للاستعلام وابحث بالتشابه الكوني (cosine similarity) بدل `ILIKE`.
3. أضف حد أدنى لدرجة التشابه لتفادي نتائج غير ذات صلة.

**معيار القبول**: استعلام بصيغة مختلفة عن الكلمات الأصلية (مرادف وليس نفس الكلمة) يرجع النتيجة الصحيحة من الذاكرة.

## المهمة 5: تدقيق الصفحات الضخمة غير الموثقة

**المشكلة**: عشرات الصفحات بأسماء طموحة (`CyberCommand4D`, `AutonomousSwarmSystemPage`, `godmode.ts`, `SwarmEvolutionPage`, `AgentEvolutionDashboard`...) بدون توثيق واضح لما تفعله فعلياً — نمط شائع لمخرجات AI سريعة بواجهات كثيرة ومنطق خلفي سطحي.

**المطلوب**:
1. لكل صفحة/route في القائمة أدناه، حدد: (أ) تعمل فعلياً وتُرجع بيانات حقيقية، (ب) واجهة فقط بدون منطق خلفي حقيقي (mock/placeholder)، (ج) مكسورة.
   - القائمة: كل ملفات `src/pages/*.tsx` وكل ملفات `src/routes/*.ts` التي تحتوي كلمات مثل `godmode`, `swarm`, `4d`, `autonomous`, `evolution`.
2. اكتب تقرير `AUDIT.md` بجدول: اسم الملف | الحالة (أ/ب/ج) | ملاحظات | أولوية الإصلاح.
3. احذف أو أخفِ من الواجهة أي صفحة من النوع (ج) حتى تُصلح، لتفادي تجربة مستخدم مضللة.

**معيار القبول**: `AUDIT.md` موجود ومكتمل، ولا توجد صفحة "مكسورة" ظاهرة للمستخدم النهائي.

## المهمة 6: مشاريع متعددة الملفات (Artifacts أعمق)

**المشكلة**: `create_artifact` يتعامل مع ملف كود واحد (HTML/React) فقط، لا يوجد نظام لإنشاء تطبيق متعدد الملفات (مكونات + تنسيق + تبعيات) شبيه بمخرجات Claude الأكثر تعقيداً.

**المطلوب**:
1. صمم بنية "مشروع افتراضي" (virtual file tree) يمكن للنموذج إنشاء/تعديل عدة ملفات فيها ضمن استدعاء واحد أو متسلسل (tool: `write_project_file`, `list_project_files`, `read_project_file`).
2. اجعل `ArtifactPanel` يعرض شجرة ملفات + معاينة تجمع الملفات (باستخدام bundler خفيف في المتصفح، مثل esbuild-wasm، أو خادم معاينة مؤقت).
3. حافظ على نفس قيود الأمان (sandbox iframe، لا شبكة خارجية إلا عبر بروكسي محكوم).

**معيار القبول**: طلب "أنشئ تطبيق React بثلاث مكونات" ينتج مشروعاً بملفات منفصلة قابلة للمعاينة والتنزيل، وليس ملفاً واحداً ضخماً.

## ملاحظات تنفيذ عامة (طبّقها في كل مهمة)

- لا تكتب "TODO" أو دوال تفشل بصمت — كل دالة يجب أن تنجح فعلياً أو ترمي خطأ واضحاً.
- أضف اختبار واحد على الأقل لكل مهمة قبل اعتبارها منتهية.
- بعد كل مهمة، شغّل `pnpm run typecheck` و`pnpm run build` وتأكد من عدم وجود كسر.
- حدّث `replit.md` (الأقسام: Where things live / Architecture decisions / Gotchas) بما يوثق كل تغيير جوهري.
- لا تحذف أي كود دون التأكد أولاً أنه غير مستخدم في أي مسار حي (grep شامل + بحث عن imports).
