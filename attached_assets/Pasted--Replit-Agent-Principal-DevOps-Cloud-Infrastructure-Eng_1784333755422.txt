أنت بصفتك Replit Agent ومهندس بنيات تحتية وسحابية خبير (Principal DevOps & Cloud Infrastructure Engineer). 

المطلوب هو إجراء "ترقية شاملة وعميقة للبنية التحتية" (Full Infrastructure & Architecture Upgrade) للمشروع الحالي، لجعله جاهزاً للعمل بكفاءة الشركات الكبرى (Production-Ready) ومقاوماً للأعطال.

يرجى تنفيذ الأنظمة والأدوات والبنيات التحتية الناقصة التالية بدقة في كامل الـ Monorepo:

1. طبقة مرونة البيانات والـ Caching (Database & Redis Resilience):
   - قم بإعداد نظام إدارة اتصالات قاعدة البيانات (PostgreSQL Connection Pooling) لضمان عدم انهيار السيرفر عند زيادة الزوار.
   - قم ببناء طبقة تخزين مؤقت ذكية (Smart Redis Caching Layer) لتخزين استجابات الـ APIs المتكررة والـ AI Sessions لتقليل الضغط على قاعدة البيانات وتسريع الاستجابة.

2. نظام مراقبة وتسجيل الأعطال المركزي (Advanced Logging & Observability):
   - قم بتوسيع إعدادات Sentry وتفعيل الـ Performance Monitoring لتتبع سرعة الـ Routes ومصادر البطء.
   - قم بإنشاء مجلد مركزي للـ Logger (باستخدام Winston أو Pino) لتسجيل كافة عمليات السيرفر والأخطاء والطلبات الواردة بصيغة JSON منظمة، لتسهيل تتبع الأعطال لاحقاً.

3. معالجة العمليات الطويلة في الخلفية (Background Jobs & Message Queue):
   - نظرًا لأن المشروع يتعامل مع الـ AI والـ Webhooks، قم بإعداد نظام طوابير (Message Queue / Task Queue) باستخدام BullMQ أو نظام معالجة مدمج مع Redis لإدارة المهام الثقيلة (مثل رفع ملفات S3 الكبيرة، أو معالجة ردود الذكاء الاصطناعي الطويلة) في الخلفية دون تعطيل استجابة السيرفر للمستخدم.

4. حماية الـ API وإدارة الحصص (API Rate Limiting & DDOS Protection):
   - قم ببناء ونشر نظام تحديد معدل الطلبات (Rate Limiting) متطور يعتمد على Redis (Redis-backed Rate Limiter)، بحيث يتم تحديد حصص مختلفة بناءً على نوع المصادقة (مثلاً: مستخدم الـ API Key له حصة مختلفة عن مستخدم الجوال أو الـ Clerk).

5. بيئة التشغيل والاختبارات التلقائية (Health Checks & CI-CD Readiness):
   - قم بإنشاء مسار خاص بالـ Health Check (`/health` و `/ready`) يفحص حيوية الاتصال بـ (PostgreSQL, Redis, S3) لتنبيهك فوراً في حال سقوط أي خدمة فرعية.
   - قم بإضافة هياكل فحص الكود والـ Linting الـ صارمة للتأكد من خلو المشروع تماماً من أي تسريب للذاكرة (Memory Leaks).

تأكد من الحفاظ على كامل التوافق الخلفي (Backward Compatibility)، وأن تعمل هذه الأنظمة والأدوات كطبقات تحتية داعمة للمشروع الحالي (React Frontend + API Server) دون كسر أي ميزة برمجية قائمة.
