═══════════════════════════════════
المهمة 4 — تفعيل Task 7 (مسارات الصوت /api/voice-live) — بدون OpenAI
═══════════════════════════════════
لا تبدأ بهذي المهمة إلا بعد نجاح المهام 1-3 بدليل فعلي.

قبل أي تعديل كود: افتح src/routes/voice-token.ts وsrc/interfaces/ws/VoiceWebSocket.ts واقرأ كيف مكتوبة تكامل الصوت حالياً. أعطني ملخص دقيق:
- هل STT (تحويل الصوت لنص) مكتوب بشكل يفترض OpenAI Whisper API حصراً، أو فيه إمكانية تبديل المزوّد (provider abstraction)؟
- هل فيه أي منطق TTS (نص لصوت) موجود أصلاً؟

بعدها:
1. STT: عدّل الكود ليستخدم Groq's Whisper endpoint (whisper-large-v3 عبر GROQ_API_KEY الموجود أصلاً — تحقق من توثيق Groq API الرسمي لصيغة الطلب الصحيحة، لا تفترضها).
2. TTS: تحقق أولاً هل Groq يوفر TTS حالياً ضمن نفس الحساب. إذا لا:
   - استخدم Web Speech API (متصفح، مجاني، بدون مفتاح) كحل مؤقت لجهة الواجهة الأمامية، أو
   - اترك TTS معطّل صراحة وأخبرني إنه يحتاج قرار لاحق بخصوص المزوّد (لا تفعّله بمفتاح وهمي أو placeholder)
3. فك تعليق السطرين في app.ts (استيراد وتسجيل voiceTokenRouter) فقط بعد ما تتأكد الكود جاهز للمسار الجديد.
4. اختبِر STT فعلياً بملف صوتي حقيقي أو تسجيل قصير، وأعطني رد الـ API الخام (النص المستخرج).
5. أعطني تقريراً منفصلاً عن هذي المهمة يوضح: أي جزء يعمل فعلياً بدليل، وأي جزء متبقي (TTS إن لم يُحل).

لا تعتبر Task 7 "مكتملة" إلا إذا STT شغّال بدليل حقيقي. TTS يمكن يُترك كمهمة متابعة منفصلة لو ما فيه حل مجاني جاهز.
